# TinyCycle-plug on PEMS

This experiment extends the [official iTransformer repository](https://github.com/thuml/iTransformer) . The TinyCycle model calls the upstream iTransformer for each phase, using its inverted embedding, encoder and output projection. An opt-in fused encoder preserves the joint QKV projection and linear feed-forward layers of the original PEMS experiment. The ordinary upstream iTransformer model uses its original encoder by default.

## Search, train and test

Use Python 3.11 or later and an NVIDIA GPU with BF16 support. The reference environment used PyTorch 2.5.1 with CUDA 12.4. Install that CUDA build, then install the remaining dependencies for this experiment.

```bash
python -m pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cu124
python -m pip install -r requirements-tinycycle.txt
```

Put `PEMS03.npz`, `PEMS04.npz`, `PEMS07.npz`, and `PEMS08.npz` in a single directory. The loader verifies their MD5 fingerprints and uses the flow channel. From the repository root, run the following with a new output directory.

```bash
python -u run.py tinycycle-phase --root_path /path/to/pems --output ./tinycycle_results > tinycycle_run.log 2>&1
```

The command generates 96 candidates per dataset using the expanded 720-step PEMS grid. It searches periods 4, 8, 12, 18, 24, 48, 72 and 144, widths 32, 64, 128 and 256, depths 1 through 4, learning rates 0.0001, 0.0003, 0.001 and 0.003, and weight decays 0.0001 and 0.001. The balanced grid uses 8 combinations per period below 24 and 16 per larger period. The seed is 2023.

Each candidate starts from random initialization and trains on the first 60% of the series. The next 20% is used for boundary calibration and promotion from 192 to 640 and then 1,600 training steps. At each promotion, the search keeps the two lowest validation MSE candidates per horizon and the two lowest by mean MSE across horizons. The first promotion also keeps the best candidate per period. The final search compares the two longer budgets on the same 320 validation origins and selects the checkpoint with the lowest validation MSE for each horizon.

The command writes `selected.json` for all four datasets before loading test targets. It then evaluates only the selected checkpoints on the last 20% and writes `per_task.csv` and `comparison.md`. Each dataset directory also contains validation scores and checkpoints generated by the run.
